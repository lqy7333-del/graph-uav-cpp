### 为什么之前的局部搜索给出 0–3%（错误结论）

| 方法 | 结果 | 原因 |
| --- | --- | --- |
| 2-opt / 交换 / relocate / 换门 | **0–3%** ✗ | 不改变**出行结构** |
| 解析下界（质心 MST）| 非法 ✗ | 边界间距 ≤ 质心间距，质心 MST 不是下界 |
| 解析下界（修正后边界 MST）| ~90% ✗ | 太松，无法判定 |
| 加法模型 DP | 41% 但**重放失败** ✗ | 漏掉载荷/补给耦合，解不可行 |
| **束搜索（真实环境神谕）** | **5.6–12.8%** ✓ | 解必然可行 ✓ |

## 4. 改进的机制（结构差异分析）

| seed | 改进主要来自 |
| --- | --- |
| 1000 | **覆盖 −1,204 m**（访问 10→9）|
| 1001 | **补给步 −462 m** |
| 1002 | **转场 −252 m + 补给步 −698 m** |

**访问次数变了（9/10/11 vs 9/10），但平均跳步基本不变（107–156 vs 108–146）** ✗

> ⇒ 改进不是「把顺序排得更短」✗，而是**改变出行结构** ✓
>
> **关键机制**：载荷耗尽时「下一个去哪个地块」决定了各地块的残留量
> ⇒ **workload 切分是顺序的副产品** ⇒ 覆盖距离（58% 成本）被顺序**间接控制** ✓

## 6. 方法论教训（本阶段最有价值的部分）

1. **训练曲线不能判断策略好坏**
   2000 轮里采样奖励 +3 分，贪心**一分未动** ✗
   熵在降只是「策略变确定」，不是「变好」✗

2. **参照物本身要先验证**
   - NN 基线曾因「门取枚举第一个」而虚高 1.2 分 ✗
   - 质心 MST 下界其实**不合法** ✗
   - 加法模型的 41% 解**根本不可行** ✗
   - 局部搜索的 0–3% 是**算子太弱** ✗

3. **两个口径会给不同答案**
   顺序最优的 checkpoint ≠ 执行最优的 checkpoint ✗
   `tour_ratio` 完全不含门的代价 ✗

4. **实验设计要先记基线**
   改特征维度前没记录 `v14@200` 的配对验证 ⇒ 旧 checkpoint 无法加载 ⇒
   **同轮数对照永久缺失** ✗

5. **受约束的动作空间会让 NP-hard 问题变简单**
   本问题的难度在「出行结构」✓，而它只被**部分**交给策略 ✗

## 7. 下一步（唯一有证据支持的方向）

**改变动作粒度** ✓ —— 让策略一次决策「一整段出行」：
去哪几块、每块覆盖多少、在哪块之后回补给 ✓

依据：束搜索的解**正好是这个结构** ✓（访问 9–11 次、含明确的补给点 ✓），
而单步动作空间表达不了它 ✗

验收协议（与本次相同）：
1. 配对 vs 两行规则 **> +0.5**
2. `beam_oracle` 差距 **< 3%**
3. `structure_diff`：访问次数接近束搜索解
4. 覆盖率 100%
