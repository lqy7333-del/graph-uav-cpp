# GA＋D→P / GA＋P→D / GA＋CC：开发协议 v0.1

状态：第一段设计基线。正式实验参数在第五段验收后冻结，目前禁止正式搜索。
两种新方法是受文献启发、适配本环境的基线，不声称复现论文的多机、多基地或部分覆盖模型。

## 1. 共同任务与比较范围

单 UAV、全任务离散覆盖、相同资源/补给/返航规则；共同实例快照、扫幅、速度和机动代理。
主目标为完整任务 total_time；辅助量为每个方案自身的 total_time−time_work_base。
work 不假定严格常数；不拿面积/扫幅/速度当已证明下界。
三组使用同一 `BoundaryAwareSweepPlanner` 的方向候选和连接逻辑。
本实验比较分区与访问安排的组织方式，不单独证明内部扫描算法的贡献。

## 2. D→P 的实现定义

1. 在初始快照上对每个地块分区，完全不读取 GA 候选访问顺序。
2. 初始条带轴取地块最小旋转外接矩形长轴；正方向与等长边按坐标确定性破同。
   按法向投影排序离散点（同投影按切向坐标、point ID），形成连续条带；
   网格邻接断开的部分拆为独立子任务，不能把不连通块伪称一个连通区域。
3. 从整个地块开始检验子任务：满资源从 depot 出发、执行指定区域、保留返航资源。
   枚举原地块合法门组合，用共享路径规划和资源判据检查是否至少有一个可行解。
   若没有，按投影累计 point_area 的中位切分，继续递归；每次须减少点数。
   单点仍不可行则报告预处理失败，禁止丢弃该点或缩小工作量。
4. 预处理完成后区域 point ID 集合冻结。外层为子任务排列，内层为门选择。
   外层使用排列保持的交叉、交换/插入变异；不删除任务或创造重复任务。
5. 若当前剩余资源无法完成下一个固定子任务，允许先返航补给，再尝试原子任务。
   满资源仍不可行的候选记失败；不在候选执行中重新划分区域。

这是一种资源可行的预分区基线，不是“随意等面积切块”。它不保证预分区最优。
预处理的路径探测次数与时间单独记录并计入在线预算。

## 3. P→D 的实现定义

1. 外层是允许重复的地块访问序列，每次访问携带严格正的覆盖权重。
   每个地块至少出现一次；交叉后缺失地块按固定 ID 顺序补入，并记录编码修复。
   每个地块的权重归一化为目标面积份额；不是直接调用 CC workload_ratio。
2. 对每个地块按其访问在序列中的次序分配剩余离散点。
   第一次及最后一次的相邻位置取 depot，其余取前后访问地块质心。
   对各次访问，以“后邻位置−前邻位置”为排序轴；零向量用地块固定长轴。
   沿轴排序，取使累计面积最接近目标份额的非空前缀（等距取较短前缀），
   为后续访问各保留至少一个点；末次获得全部余点。
   访问数超过点数的候选拒绝，不产生空访问。记录实际面积与目标面积偏差。
3. 各区域按网格邻接拆连通块；实际执行次序固定为投影/point ID 排序，记录拆块。
   对满资源仍不可行的区域，用 D→P 同一中位切分规则拆成相邻子访问，直到可行
   或单点失败。修复只允许拆分，不允许跨原访问重分配、合并或改全局顺序。
4. 内层搜索门选择；当前资源不足时先补给。所有区域仍走共享扫描器/执行器。
   修复上限由离散点数和统一任务 max_steps 共同限制，超限候选失败。
5. 必须记录份额误差、拆分次数、补给次数、修复后访问数及不同染色体是否解码同解。
   若 repair 大量抹去编码差异，第五段不得将该实现直接当成熟基线。

这是“先访问安排与份额、后生成区域”的适配基线，不是先生成完整覆盖路线再切断。
几何修复是方法的一部分，必须公开并计时。

## 4. CC 与共享执行接口

CC 保留现有 field/entry/exit → workload refinement → region generator → sweep 的规则。
新基线持有 `RegionTask(task_id, field_id, point_ids)`，ID 来自冻结实例，不持有可变 GridPoint。
执行时解析到当前环境的点，拒绝未知点、重复所有权、空区域和已完成点的重复任务。
P→D/D→P 的离散完整分配由 `validate_partition` 校验；它不证明实际扫幅覆盖。

阶段 2 增加纯规划产物（区域 ID、门、起点、分段路径、扫描段、实例/状态标识），
规划无物理副作用；执行前重新验证当前状态、路径连接和资源及返航储备。
先整体检查三段路径，再原子执行；任何错误回滚 UAV/覆盖/heading/时间/轨迹/日志/缓存。
已生成路径不可偷偷重规划；跨状态使用旧规划应明确拒绝。
新入口不能调用 CC 的 estimate_workload/refine 来重新生成区域。
覆盖标记与扫描几何关系须独立审计，不允许仅因给了 point IDs 就宣称物理覆盖完成。

补给触发是方法解码的一部分：新基线按下一指定任务可行性触发，CC 保留现有动作可行性规则。
补给动作物理结算必须相同。此差异应报告，不能声称三组除分区外完全单变量。

## 5. 搜索与预算

优先复用 GA 的种群选择、精英保留、inner quota、完整 incumbent 和中断记录；
各自编码/算子不同必须显式命名。禁止用 RL 初始化任何一组。
正式候选方案：outer 4×6 scored rounds，inner 8×2，含初始化共最多 385 次完整任务候选尝试；
或在线 1800 秒，先到者停止。失败/中断尝试也计数。
所有实例相关初始化、区域划分、路径探测、修复和搜索在计时范围内；独立重放另报。
局部路径探测不冒充完整任务评估，单独记次数/耗时并受同一墙钟限制。
不能因为预算没找到完整解而免费调用 CC 补全；保留失败，报告完成率。

旧 CC 在 `NestedGA.run()` 启动计时，构造函数 deepcopy 不在搜索时间内。
复用旧结果时三组共同快照装载/初始 clone 作为 setup 单列；D/P 特有预处理不能放进 setup。
若统一执行改动造成旧 CC 轨迹/成本变化，必须停止复用并报告，不直接拼表。

## 6. 验收与报告

开发：3–5 个新 10 地块实例，先验证再定正式参数；不得看正式成绩后调整分区规则。
正式：已有共同 10/20 地块面板、seed42；现阶段是开发对照，非新的 sealed 确认。
主表：完成率、总时间、各自扣除 work 后时间、四分项、在线计算时间。
搜索曲线同时给实际候选数和墙钟；分区修复、预算停止、fallback 均报告。
主比较 D→P−CC、P→D−CC，实例配对区间，单搜索 seed/单冻结策略的限制显式保留。
若有失败，不只在各方法各自成功子集上比较平均时间；先报告完成率，完整配对子集仅辅助。
不把曲线平台当全局收敛，不把成本分项相关性当独立因果证明。
